Deterministic reconciliation

The important checks deliberately remain in TypeScript rather than being delegated to the model:

const variance =
  Math.abs(invoice.value - customs.value) /
  Math.max(invoice.value, 1);

if (variance > 0.01) {
  findings.push({
    code: "VALUE_VARIANCE",
    severity: variance > 0.05 ? "HIGH" : "MEDIUM",
    title: "Invoice and customs values differ",
    evidence: [
      {
        source: invoice.number,
        field: "invoice.value",
        value: invoice.value
      },
      {
        source: customs.declaration,
        field: "customs.value",
        value: customs.value
      }
    ]
  });
}


The 1% and 5% values are demonstration thresholds, not statutory or professional tax thresholds.

The prototype also detects:

invoice versus customs Incoterm differences;
invoice versus ERP revenue differences;
insufficient evidence supporting a finding.
Why this split is important

Gemini is not allowed to:

calculate the source values;
rewrite evidence;
determine the variance;
create source-document identifiers;
decide whether an exact numerical reconciliation succeeds.

Gemini is used only to improve the narrative explanation, subject to Zod validation.

Google’s structured-output documentation states that Gemini can be configured to generate responses conforming to a JSON schema, including through Zod in JavaScript.

The implementation uses the current @google/genai TypeScript/JavaScript SDK. Google describes that SDK as supporting both the Gemini Developer API and relevant Google enterprise-hosted Gemini APIs.

The Gemini adapter is deliberately isolated:

export async function generateStructured<T>(
  prompt: string,
  schema: ZodType<T>,
  fallback: T
): Promise<T> {
  if (!client) return fallback;

  const response = await client.models.generateContent({
    model: process.env.GEMINI_MODEL || "gemini-2.5-flash",
    contents: prompt,
    config: {
      responseMimeType: "application/json"
    }
  });

  const parsed = JSON.parse(response.text || "{}");
  return schema.parse(parsed);
}


For the next refinement, pass a formal response schema to Gemini as well as validating it afterward. Google recommends combining a response schema with the JSON MIME type when strict structured output is required.

A production adapter would look like:

import { v1 as documentai } from "@google-cloud/documentai";

const client = new documentai.DocumentProcessorServiceClient();

export async function processDocument(
  content: Buffer,
  mimeType: string
) {
  const name =
    `projects/${process.env.GCP_PROJECT_ID}` +
    `/locations/${process.env.DOCUMENT_AI_LOCATION}` +
    `/processors/${process.env.DOCUMENT_AI_PROCESSOR_ID}`;

  const [result] = await client.processDocument({
    name,
    rawDocument: {
      content: content.toString("base64"),
      mimeType
    }
  });

  return {
    text: result.document?.text ?? "",
    pages: result.document?.pages ?? []
  };
}

4. Reconciliation Engine

This should be deterministic TypeScript, not an LLM:

function reconcileTransaction(tx: CrossBorderTransaction): Finding[] {
  const findings: Finding[] = [];

  if (tx.customsValue && tx.invoiceValue.currency === tx.customsValue.currency) {
    const variance =
      Math.abs(tx.invoiceValue.amount - tx.customsValue.amount) /
      tx.invoiceValue.amount;

    if (variance > 0.01) {
      findings.push({
        type: "VALUE_VARIANCE",
        severity: variance > 0.05 ? "HIGH" : "MEDIUM",
        variance,
        evidence: [tx.invoiceValue.source, tx.customsValue.source],
      });
    }
  }

  return findings;
}


The exact threshold should be explicitly labelled as a demo policy, not a legal threshold.

7. Two additional concepts if BorderLens is not selected
Alternative A: “TP Method Navigator”

An evidence-grounded assistant that classifies a controlled transaction, constructs a FAR profile, evaluates CUP/RPM/cost-plus/TNMM/PSM applicability, and produces a method-selection matrix with evidence and reviewer controls.

This connects well with your existing knowledge. Internal TP training materials identify comparability factors including property or service characteristics, FAR, contractual terms, economic circumstances, and business strategies. They also emphasize assessing whether differences materially affect price or margin and whether reliable adjustments are possible.

Strength

Highly domain-specific and difficult for a generic team to reproduce.

Weakness

Method selection is nuanced and difficult to demonstrate safely in three minutes. The product must clearly present its output as a review aid, not an automated tax conclusion.

Alternative B: “ComparableScreen AI”

An explainable comparable-company screening workbench that:

imports candidate companies;
normalizes company names;
applies deterministic quantitative screens;
analyzes business descriptions;
extracts acceptance/rejection evidence;
produces a review trail;
supports human override.
Strength

Excellent demonstration of structured plus unstructured processing.

Weakness

Real commercial databases may create licensing problems. Use a synthetic dataset or openly licensed public company descriptions.

Alternative C: “CloseGuard AI”

An accounting close and tax-reconciliation assistant that connects:

trial balance;
general ledger;
tax adjustments;
intercompany balances;
invoices;
tax-return working papers.

It flags unreconciled balances and drafts follow-up questions.

Strength

Easier for judges to understand.

Weakness

14. Important compliance boundary

Do not use:

confidential client documents;
employer-owned templates;
proprietary databases;
internal methodologies copied into a public repository;
identifiable client transaction data;
internal emails or deliverables.

The competition requires a public GitHub repository, so all sample information should be synthetic, public, or appropriately licensed. Internal guidance also emphasizes that professional judgment and accountability remain with professionals even where AI assists with research, review, analysis, and drafting.

Add a prominent product statement:

“BorderLens AI is a professional review-support prototype. It does not provide legal or tax advice and does not autonomously determine customs value, transfer prices, tax liabilities, or filing positions.”

Final recommendation

Build BorderLens AI as a focused, evidence-grounded “transaction digital twin” for one cross-border related-party transaction.

The winning combination is:

A problem you understand deeply
+ a Google-native deployed prototype
+ meaningful Gemini use
+ deterministic financial reconciliation
+ explicit multi-agent control
+ source-level evidence
+ human professional approval
+ a polished three-minute story


The differentiator is not “we used several agents.” It is:

We turned five inconsistent business records into one controlled transaction model, detected material discrepancies, showed the evidence, and preserved professional accountability.
